# SecureBugBounty Platform

> Веб-платформа для управления сообщениями об уязвимостях, bug bounty и CTF-задачами.

## О проекте

**SecureBugBounty Platform** — учебный full-stack проект в области информационной безопасности, объединяющий два направления:

- приём и управление отчётами об уязвимостях;
- проведение CTF-соревнований с системой динамического начисления баллов и рейтингом участников.

Проект включает веб-интерфейс, панель администратора, REST API, аутентификацию, разграничение прав доступа, защитные механизмы API, SQLite и Docker-конфигурацию.

---

## Возможности

### Отчёты об уязвимостях

- Создание отчётов об обнаруженных уязвимостях.
- Указание названия, критичности, описания, шагов воспроизведения, влияния и рекомендаций.
- Отслеживание статуса отчёта.
- Начисление баллов за принятые отчёты.
- Просмотр и изменение отчётов администраторами.

### CTF-модуль

- Создание и управление CTF-задачами.
- Категории и описания заданий.
- Проверка флагов.
- Динамическая система начисления баллов.
- Уменьшение стоимости задачи по мере увеличения количества решивших её участников.
- Защита от повторного решения одной задачи одним пользователем.
- Автоматическое обновление рейтинга.

### Аутентификация и авторизация

- JWT-аутентификация.
- Хеширование паролей с помощью bcrypt.
- Разделение ролей:
  - `USER`
  - `ADMIN`
- Защищённые административные endpoints.
- Ограниченный срок действия JWT-токенов.

### Защита приложения

- Ограничение частоты запросов (rate limiting).
- Проверка и очистка входных данных.
- Security HTTP headers.
- Пароли не возвращаются через API.
- Параметризованные SQL-запросы.
- Запуск Docker-контейнера от непривилегированного пользователя.
- Gunicorn для production-запуска.

### Панель администратора

Администратор может:

- управлять пользователями;
- просматривать и изменять отчёты;
- создавать и удалять CTF-задачи;
- применять штрафные баллы;
- просматривать рейтинг участников.

## Локальный запуск

### 1. Клонирование репозитория

```bash
git clone https://github.com/zhenis04/securebugbounty-platform.git
cd securebugbounty-platform
```

### 2. Создание виртуального окружения

#### Windows

```powershell
python -m venv .venv
.venv\Scripts\activate
```

#### Linux / macOS

```bash
python3 -m venv .venv
source .venv/bin/activate
```

### 3. Установка зависимостей

```bash
pip install -r requirements.txt
```

### 4. Настройка переменных окружения

Перед запуском рекомендуется установить собственный секретный ключ.

#### Windows PowerShell

```powershell
$env:SECRET_KEY="your-long-random-secret"
$env:DEBUG="false"
```

#### Linux / macOS

```bash
export SECRET_KEY="your-long-random-secret"
export DEBUG="false"
```

### 5. Запуск

```bash
python app.py
```

После запуска приложение будет доступно по адресу:

```text
http://127.0.0.1:5000
```

Панель администратора:

```text

```

## Система начисления баллов

CTF-модуль использует динамическую систему оценки сложности.

Для каждой задачи используются:

```text
Максимальное количество баллов
Минимальное количество баллов
Шаг уменьшения
Количество решивших
```

Текущая стоимость задачи рассчитывается по принципу:

```text
current_points = max(
    minimum_points,
    maximum_points - decay × (solve_count - 1)
)
```

Таким образом, стоимость задачи может постепенно уменьшаться по мере того, как её решает больше участников, но не опускается ниже установленного минимального значения.

## База данных

Приложение использует SQLite.

Основные сущности:

```text
users
  │
  ├── reports
  │
  └── solves ─── challenges
```

### Основные таблицы

- `users` — пользователи, роли и количество баллов.
- `reports` — отчёты об уязвимостях и их статусы.
- `challenges` — CTF-задачи и параметры начисления баллов.
- `solves` — история решений задач и начисленных баллов.

## Реализованные меры безопасности

В проекте продемонстрированы следующие подходы к безопасной разработке:

- хеширование паролей с bcrypt;
- JWT-аутентификация;
- разграничение прав доступа по ролям;

- CSRF-защиту там, где она применима;
- безопасную настройку cookies и сессий;
- централизованное логирование;
- мониторинг событий безопасности;
- резервное копирование БД;
- PostgreSQL или другую production-БД;
